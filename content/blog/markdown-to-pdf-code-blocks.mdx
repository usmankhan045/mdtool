## Why Code Blocks Are the Hardest Part of Markdown to PDF Conversion

If you've ever tried to convert a Markdown file with code blocks into a PDF, you've almost certainly run into at least one of these problems:

- Monospace font not used, so code renders in the same proportional font as body text
- No syntax highlighting, so everything is plain black text
- Lines overflow the page and get cut off
- Indentation is lost, making code unreadable
- Background color disappears, so code blocks look identical to normal paragraphs

These aren't random bugs. They happen because most tools take a shortcut: they parse Markdown into HTML, then dump it into a PDF renderer that ignores CSS entirely. Code blocks depend heavily on CSS (`font-family: monospace`, `white-space: pre`, `overflow-x: auto`, background colors), and when CSS is stripped out, code becomes unreadable.

## What Broken Code Blocks Look Like

Here's a concrete example. Take this simple JavaScript function in a Markdown file:

````markdown
```javascript
async function fetchUser(id) {
  const response = await fetch(`/api/users/${id}`);
  if (!response.ok) throw new Error("User not found");
  return response.json();
}
```
````

A **broken PDF converter** will output something like this in the PDF:

```text
async function fetchUser(id) { const response = await fetch("/api/users/" + id); if (!response.ok) throw new Error("User not found"); return response.json(); }
```

No line breaks. No monospace. No background. Just a wall of text that's impossible to read.

A **correct PDF converter** preserves:
- The monospace font (`Courier`, `Fira Code`, or similar)
- Each line on its own line with proper indentation
- A light gray or dark background that visually separates code from prose
- Syntax-colored tokens (keywords, strings, functions) if it supports highlighting

## The Real Code Example

Here's the full JavaScript snippet we'll use to test PDF output throughout this guide:

```javascript
// Illustrative example: a minimal browser-side Markdown to PDF function.
// (Not MDTool's own code; MDTool builds a vector PDF with pdfmake instead.)
async function convertMarkdownToPDF(markdownContent) {
  // Parse Markdown into an HTML string
  const { marked } = await import("marked");
  const htmlContent = marked.parse(markdownContent);

  // Wrap in a styled document for proper PDF rendering
  const styledHTML = `
    <!DOCTYPE html>
    <html>
      <head>
        <style>
          body { font-family: Georgia, serif; line-height: 1.6; }
          pre  { background: #f4f4f4; padding: 1rem; border-radius: 4px; overflow-x: auto; }
          code { font-family: 'Courier New', monospace; font-size: 0.9em; }
        </style>
      </head>
      <body>${htmlContent}</body>
    </html>
  `;

  // Use html2pdf.js (browser only — never run server-side)
  const html2pdf = (await import("html2pdf.js")).default;
  return html2pdf()
    .set({ margin: 10, filename: "output.pdf", html2canvas: { scale: 2 } })
    .from(styledHTML)
    .save();
}
```

Notice the three things that make this work: the `<pre>` element gets a background and padding, `code` gets a monospace font, and `html2pdf.js` is imported dynamically so it only ever runs in the browser, never on the server where `window` is undefined.

The catch with this approach is that `html2pdf.js` takes a picture of the page with `html2canvas`. The code in the PDF is an image: you can't select or search it, and it blurs when you zoom. That's why MDTool switched to `pdfmake`, which writes the code into the PDF as real text, with the highlight colors applied to each token.

## Common Problems and Fixes

**Problem: Code lines are cut off at the right edge of the page**
Fix: Make sure your code lines are under ~80 to 90 characters. The converter wraps very long lines, but it can't reformat code logic. Break long lines manually before converting.

**Problem: Syntax highlighting doesn't appear**
Fix: Add a language tag after the opening triple backtick. ` ```js ` instead of just ` ``` `.

**Problem: Indentation collapses to a single space**
Fix: Use spaces, not tabs. Some PDF renderers collapse tab characters. Replace tabs with 2 or 4 spaces.

**Problem: Code block background is hard to see when printed**
Fix: Every theme gives code blocks a tinted background and a border, but the light themes use a very pale gray that some printers barely show. Academic has the darkest code border of the light themes. For on-screen reading, the Dark theme gives the strongest contrast.

**Problem: A Mermaid diagram shows up as code**
Fix: The fence must be tagged exactly ` ```mermaid `. If the diagram has a syntax error, the block stays as code; check the live preview, which shows the same result the PDF will.

## Frequently Asked Questions

**Q: Does MDTool support syntax highlighting for all programming languages?**

It supports JavaScript, TypeScript, Python, Bash, JSON, YAML, HTML/XML, CSS, SQL, Go, Rust and Dart. The underlying parser uses [`marked`](https://marked.js.org/) with [`highlight.js`](https://highlightjs.org/) for token coloring. If your language isn't highlighted, formatting (monospace font, background, indentation) is still preserved, and only color tokens are skipped.

**Q: Will the code block look the same in the PDF as in the preview?**

Very close. The PDF is built from the same rendered HTML you see in the preview, with the same token colors, indentation and diagrams. Fonts can differ slightly: code uses Courier in the PDF, and long lines wrap to fit the page.

**Q: Can I convert a file with hundreds of lines of code?**

Yes. Because the PDF is built as text rather than as an image, long files stay small and sharp. Very large documents take longer to build in the browser, so for files with thousands of lines of code, split them into sections or use page breaks to keep each section readable.

**Q: My code has backticks inside the code block. How do I escape them?**

Use four backticks to open and close the fenced block instead of three. This allows triple backticks inside the block without escaping.

**Q: Is there a file size limit?**

There's no server-side limit because conversion happens in your browser. The practical limit is your device's RAM, and most modern machines handle Markdown files up to several megabytes without issue.

**Q: Can I use MDTool for confidential code?**

Yes. Because conversion is entirely client-side, your code is never transmitted to any server. You can use it for proprietary or sensitive code with confidence.
