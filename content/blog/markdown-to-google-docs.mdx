To get Markdown into Google Docs, you have three options. Turn on **Tools → Preferences → Enable Markdown** and right-click **Paste from Markdown**, open the `.md` file directly with **File → Open → Upload**, or convert it to `.docx` first and upload that. All three map `#` headings to real Docs heading styles.

Which one to pick depends on what is in your Markdown. A short note with headings and bullets survives any route. A technical document with tables, fenced code and images needs more care. Below is what each method does, step by step, and where each one falls short.

## Does Google Docs support Markdown natively?

Yes. Google added Markdown import and export to Docs in July 2024, rolling it out to all Workspace customers, Workspace Individual subscribers and personal Google accounts ([Google Workspace Updates](https://workspaceupdates.googleblog.com/2024/07/import-and-export-markdown-in-google-docs.html)). There are two separate switches to know about:

- **Import and export** of `.md` files is on by default. You don't need to change any settings.
- **Copy as Markdown** and **Paste from Markdown** are off by default. You enable them per account under **Tools → Preferences → Enable Markdown**.

The same preference also turns on autoformatting while you type, so typing `## ` at the start of a line becomes a Heading 2. Google's help page notes that heading creation through Markdown works in Docs only (not Slides or Drawings), supports six levels, and needs a space between the `#` signs and the text ([Google Docs Editors Help](https://support.google.com/docs/answer/12014036)).

## How do you paste Markdown into Google Docs?

This is the fastest route when your Markdown is in a chat window, a code editor or a GitHub file view.

1. Open any Google Doc.
2. Go to **Tools → Preferences**, tick **Enable Markdown**, and click **OK**.
3. Copy your Markdown source (the raw text with `#`, `**` and `-` characters, not a rendered preview).
4. In the doc, right-click where you want the content and choose **Paste from Markdown**.

Docs converts the syntax into native formatting as it pastes: headings become Heading 1 to Heading 6, `**bold**` becomes bold, lists become Docs lists, and links stay clickable. A plain **Ctrl+V** (**Cmd+V** on Mac) pastes the raw characters instead, which is the most common reason people think the feature is broken.

If you copied from a rendered page (a GitHub README view, for example), you are copying HTML, not Markdown. Use the **Raw** button on GitHub, or open the source file, so the clipboard holds actual Markdown.

## How do you import a .md file into Google Docs?

When the Markdown already lives in a file, open it directly:

1. In Google Docs, click **File → Open**.
2. Switch to the **Upload** tab and choose your `.md` file.
3. The file uploads and opens as a Google Doc.

From Google Drive the steps are: upload the `.md` file, right-click it, and choose **Open with → Google Docs**. Both routes are documented on Google's [Markdown help page](https://support.google.com/docs/answer/12014036). The result is a new Google Doc; your original `.md` file stays in Drive untouched.

## Why convert to .docx first?

Google Docs has imported Word files for over a decade, and its `.docx` handling is mature. Uploading a Word file gives you a predictable result because the structure is already expressed in Word's own style system rather than in Markdown syntax that Docs has to interpret.

This route makes sense when:

- you want to check the document in a Word-style preview before it reaches Docs,
- you also need a `.docx` copy for someone who uses Microsoft Word,
- your Markdown uses GFM tables or fenced code that you want to arrive as real tables and monospaced blocks.

The steps:

1. Paste your Markdown into the [Markdown to Word converter](/markdown-to-word). It runs in your browser, so the file is never uploaded to a server.
2. Click download to get a `.docx`. Headings are written as Word's native **Heading 1** to **Heading 6** styles, tables become Word tables, and lists become real Word lists.
3. In Google Drive, click **New → File upload** and select the `.docx`.
4. Double-click the file. It opens in Docs, possibly in Office compatibility mode. Click **File → Save as Google Docs** to make a native copy ([Google Docs Editors Help](https://support.google.com/docs/answer/6055139)).

Because the headings are true styles, they show up in Docs' **document outline** (the panel on the left) and in any table of contents you insert with **Insert → Table of contents**. That is the test of whether a conversion worked: if your headings appear in the outline, the structure survived. If they are just big bold text, it didn't.

Two limits worth knowing: MDTool's Word export does not yet render Mermaid diagrams or embed images. Code blocks come through as monospaced Courier New paragraphs without syntax colours. For a full rundown of the Word side, see [Markdown to DOCX](/blog/markdown-to-docx).

## Which method should you use?

| Method | Steps | Headings | Tables | Fenced code | Images |
|---|---|---|---|---|---|
| Paste from Markdown | Enable once, then right-click | Heading 1-6 styles | Works for clean pipe tables; check the result | No syntax highlighting | Not reliable; remote URLs may not load, relative paths never do |
| File → Open → Upload (.md) | 3 clicks | Heading 1-6 styles | Clean pipe tables convert; check the result | No syntax highlighting | Relative paths can't resolve |
| .docx via MDTool, then upload | Convert, download, upload | Heading 1-6 styles | Word tables | Monospaced paragraphs | Not embedded yet; insert in Docs |

Two rules of thumb from using all three. For anything under a page with simple formatting, **Paste from Markdown** is the quickest and needs no files. For long documents, or when you need a Word copy anyway, the `.docx` route gives you a file you can inspect before it reaches Docs.

## What breaks when Markdown goes into Google Docs?

No method is perfect, because Docs is a word processor and some Markdown constructs have no direct equivalent.

**Tables.** GitHub Flavored Markdown pipe tables need a header row and a separator row (`|---|---|`). If either is malformed, a pasted table can arrive as rows of literal pipe characters. Docs tables also have no column alignment from `:---:` syntax. Run tables through the [Markdown table generator](/markdown-table-generator) first if you are unsure they are well formed, and check the [Markdown tables guide](/markdown-cheat-sheet/tables) for the exact syntax.

**Code blocks.** Google Docs has no syntax highlighting, so colour is lost on every route. Indentation inside code is usually kept, but watch long lines: Docs wraps them at the page margin, which can make code harder to read. If code fidelity matters, a PDF from the [Markdown to PDF converter](/markdown-to-pdf) keeps highlighting.

**Images.** Markdown images are references, not embedded data. `![diagram](./img/flow.png)` points to a file on your disk or in a repository, which Google Docs has no access to. Plan to insert images manually with **Insert → Image** after conversion.

**Mermaid diagrams, task lists, footnotes and HTML.** Mermaid code fences arrive as plain text because Docs doesn't render diagrams. Render them to an image first and insert that. Task list checkboxes (`- [ ]`) and raw HTML tags are not part of Google's documented Markdown support, so expect to fix them by hand.

**Nested lists.** Two levels generally convert cleanly. Deeper nesting depends on consistent indentation in the source; mixing tabs and spaces is the usual cause of a flattened list.

## How do you check the result?

Spend 30 seconds on these after any conversion:

1. Open the outline from the **View** menu (it lives in the left-hand tabs and outline panel) and confirm every heading appears at the right level.
2. Scroll to each table and check the header row is bold and the column count is right.
3. Search the doc (**Ctrl+F**) for `|`, `**` and three backticks. Any hits mean some syntax was pasted as text.
4. Check links by hovering over a few of them.

If you later need the content back in Markdown, Docs can export it too. That reverse path is covered in [Google Docs to Markdown](/blog/google-docs-to-markdown).

## Frequently Asked Questions

**Q: Why don't I see "Paste from Markdown" when I right-click?**

The option is off by default. Open **Tools → Preferences**, tick **Enable Markdown**, and click **OK**. The setting applies to your account, so you only need to do it once. If it still doesn't appear, your Workspace admin may be on a delayed release schedule.

**Q: Can I open a .md file in Google Docs without converting it?**

Yes. Use **File → Open → Upload** inside Docs, or upload the file to Drive and choose **Open with → Google Docs**. Docs creates a new Google Doc from it and leaves the original `.md` file unchanged in Drive.

**Q: Do Markdown headings become real Google Docs headings?**

Yes, on all three routes. `#` through `######` map to Heading 1 through Heading 6, so they appear in the document outline and in an inserted table of contents. The `.docx` route also preserves them because MDTool writes Word's native heading styles.

**Q: Will images in my Markdown show up in Google Docs?**

Usually not. Markdown images are links to files, and relative paths like `./images/chart.png` point to your computer, which Google Docs can't reach. Insert images manually with **Insert → Image** after converting.

**Q: Is it safe to convert confidential Markdown with MDTool before uploading to Docs?**

MDTool converts Markdown to `.docx` entirely in your browser, so the content is not sent to MDTool's servers. The file only leaves your machine when you upload it to Google Drive yourself.
